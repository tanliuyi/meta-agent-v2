# Generate EIA Process Flow Diagrams

根据工艺说明、设备清单、物料去向和产污信息，生成可编辑的环评风格工艺流程及产污节点图。本技能不替代正式工程设计图、P&ID、物料衡算或污染源强核算。

## Inputs


收集并区分以下资料：

- 原料、产品和中间物料
- 工艺步骤、设备和工艺参数
- 公用工程输入
- 废气、废水、固体废物和噪声信息
- 污染源编号及污染物名称
- 治理设施、排放、回用、外售和处置去向
- 图题、图号和报告编制要求

未提供的内容标记为“待确认”，不得臆造工程数据。

## 图件样式

统一采用环评报告中的黑白线稿表达：

- 中文使用宋体或同类衬线字体，正文和节点文字保持清晰、端正、紧凑。
- 工艺设备和处理单元使用白底、黑色细边框矩形；节点尺寸随文字和工艺信息调整。
- 物流使用黑色实线和实心三角箭头；箭头方向必须与实际物流一致。
- 回用、循环、公用工程、污染物和排放去向通过标签、线型或虚线边界区分，不依赖彩色表达。
- 污染源编号、污染物、排放口、外排、回用和处置去向直接标注在对应节点或连线附近。
- 工艺区域、循环区域或厂界范围可使用灰黑色虚线边界；边界使用 `type: "boundary"` 节点渲染，不参与物流连线，区域标题置于边界上沿。
- 图例使用独立 `type: "legend"` 节点或图例集合，说明生产单元、产污单元、废水/废气处理单元、线型和颜色含义；图例不得嵌套在普通工艺节点中。
- 图题和图号置于图件底部，格式遵循报告编制要求。
- 版式可采用纵向、横向或分区布局；具体方向和位置根据工艺拓扑、回流关系及文字可读性确定。
- 采用分区网格：主工艺线置于中轴，废水节点置于左侧，废气和噪声置于右侧，固废置于最外侧；同一分区内节点按来源顺序排列。
- 主工艺线的相邻节点保持统一中心线和稳定垂直间距；分区之间预留不少于一个节点高度的空白通道，节点正文不得压在线上。
- 多条线汇入同一治理设施时，必须使用显式正交拐点或独立收集节点；每条汇聚线使用独立的横向入口和纵向通道，禁止依赖自动路由叠线。
- 相邻平行连线的通道中心至少间隔 24 px，连线标签避开节点边框、箭头和其他标签；无法满足时应扩大画布或拆分治理节点。
- 连接方向应显式设置为上下、左右或对应的单侧句柄；主线使用 `source-bottom` 到 `target-top`，侧向产污线使用固定侧向句柄，避免因节点坐标变化产生方向跳变。
- 版式完成后必须通过缩放适配、整图截图和节点/连线计数检查，确认没有节点遮挡、线条交叉或标签重叠。

## 操作流程

使用 CLI 查询、修改、校验和导出流程图。结构化数据通过 JSON 文件传递，完成修改后必须执行校验。

```bash
node scripts/eia-flow.mjs diagram get
node scripts/eia-flow.mjs diagram validate
node scripts/eia-flow.mjs node add --file node.json
node scripts/eia-flow.mjs node update N10 --file patch.json
node scripts/eia-flow.mjs node delete N10
node scripts/eia-flow.mjs edge add --file edge.json
node scripts/eia-flow.mjs edge update E10 --file patch.json
node scripts/eia-flow.mjs edge delete E10
node scripts/eia-flow.mjs export csv --output pollution.csv
```

执行以下操作：

1. 读取现有图数据和项目资料。
2. 使用稳定 ID 生成或修改节点、连线及环评字段。
3. 执行 `diagram validate`。
4. 校核污染源、治理路径和最终去向。
5. 导出图数据或清单，并列出待确认资料。

## EIA Compilation Context

流程图用于支撑环境影响报告书/表中的建设项目工程分析和污染源识别。编辑数据时，可按项目资料记录以下关系：

- 建设内容、生产工艺、原辅材料和公用工程之间的关系。
- 生产工序、储运环节、非正常工况和产污环节之间的关系。
- 废气、废水、固体废物、噪声等污染物的产生节点、收集方式、治理措施和排放/处置去向。
- 污染源编号、污染物名称、排放口、排放方式和治理设施与正文、源强核算、污染防治措施之间的对应关系。
- 物料回用、循环利用、外售、送污水处理站和委外处置等去向。

图件表达应以现行国家和地方生态环境管理要求、适用行业技术导则、项目环评类别及编制模板为依据。默认采用本技能规定的图件样式；用户可以新增自定义节点类型、连线类型、编号体系、图例和版式。

## Workflow

1. 读取工艺资料，记录图名、图号、页面比例、字体、流程框、线宽、箭头、虚线边界、污染源标注和图题格式。
2. 使用 `references/diagram-data-model.md` 建立流程图数据模型，节点和连线使用稳定 ID。
3. 根据工艺拓扑、回流关系和文字可读性确定布局。
- 绘制生产工序、治理设施、储存设施、产污节点、输入节点和去向终点，并为节点配置名称、类型、尺寸、填充色、边框、字号、坐标及环评属性。
- 需要表达工艺单元、回收单元或厂界范围时，使用 `type: "boundary"` 节点；边界节点只负责视觉分区，不应作为连线端点。
- 需要表达图例时，使用独立 `type: "legend"` 节点或图例集合，至少覆盖节点类别、物料实线、污染物流虚线及颜色含义。
5. 绘制物料流、污染物流、回用流和辅助流，配置线条颜色、粗细、实线/虚线、路由、箭头和标签样式，并保持连接关系与数据一致。
6. 在实际产污位置添加 `G`、`W`、`S` 等项目约定的污染源编号、污染物名称和去向。
7. 使用 CLI 完成数据修改、校验和导出。
8. 导出 SVG、PNG、JSON、CSV、Mermaid 或 HTML；需要 DOCX 或 PPTX 时，再将矢量图嵌入目标文档。
10. 校核节点类型、连接关系、回流关系、治理路径、污染源编号、文字可读性、图例和图题。
11. 输出图数据、流程简述、产污节点清单和待确认资料。

## Diagram Rules

- 流程方向和布局依据工艺拓扑、回流关系和文字可读性确定。
- 主工艺线采用统一中心线；废水、废气、固废和噪声分别放置在独立分区，不得与主线交叉。
- 多源汇入同一治理节点时必须配置显式 `waypoints` 或独立收集节点；每条线使用独立通道，通道中心至少间隔 24 px。
- 主线连线显式使用 `source-bottom`/`target-top`；侧向连线显式指定句柄，禁止让自动方向选择在相邻节点之间跳变。
- 连线标签必须位于空白通道内，不能覆盖节点、箭头或其他标签；空间不足时先扩大分区间距，再缩小文字。
- 布局完成后执行整图截图检查，并确认节点、连线、标签均无遮挡或重叠。
- 回用或循环物流按照其实际连接关系布置，并与主流程保持可区分性。
- 公用工程按照实际输入关系布置。
- 废气、废水和固废使用项目约定的污染源编号，例如 `G3-1`、`W3-1`、`S3-1`；编号规则由用户或项目资料确定。
- 治理设施按照污染物产生、收集、治理和最终去向的实际关系布置。
- 虚线边界、实线箭头、虚线箭头和图例的含义必须在资料或图例中明确。
- 图件表达应支持白底黑框工艺节点、虚线区域边界、独立图例、带标签的实线/虚线/点线物流，以及显式正交拐点。
- 入口、出口和终点节点可以只有单侧连接；其他节点的连接数量按照其节点类型和工艺资料校核。
- 缺少工程资料时使用“待确认”，不得编造真实工艺参数或污染源强。

## Data Integrity

- 节点 ID 和连线 ID 必须唯一且非空。
- 连线端点必须引用现有节点。
- 删除节点时删除关联连线，避免悬空引用。
- 污染源、治理设施和最终去向应能从流程数据中追踪。

## Deliverables

- 数据、产污节点清单、流程简述和待确认事项。

## Verification

- CLI 可以完成流程图查询、校验、保存以及节点和连线 CRUD。
- 节点和连线修改后，保存并重新加载仍保持数据一致。
- 删除节点后不存在关联悬空连线。
- 非法 ID、重复 ID、缺失字段和无效端点会被拒绝，且不会部分写入。
- 每个节点的输入输出关系符合节点类型和工艺资料；入口、出口和终点允许单侧连接。
- 污染源编号、污染物、治理设施和最终去向在图和清单之间一致。
- 箭头、回流、治理路径、虚线边界、图例、图题和文字布局经过检查。
